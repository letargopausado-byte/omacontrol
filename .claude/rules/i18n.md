# Words, and the languages they are read in

> **Read this when:** you write or change a word the reader sees — a label, a description, a note, a heading, a button, an empty state — in a page, a component or `lib/`, or you touch a catalog in `i18n/`.

## The words live in the catalog

Nothing the reader sees is written into a page. It is a key, and the key's
English is in `i18n/en.json`:

```qml
label: Ui.Strings.t("windows.innerGaps")            // in sections/ and the root files
label: Local.Strings.t("ui.textRow.save")           // in ui/
```

`ui/Strings.qml` is one `Commons.Translations` for the whole window, which
is Omarchy's own way for a plugin to carry its catalogs. It follows the
language picked under **Setup > Language** — the same file the shell reads —
and falls back a string at a time: `es-MX` to `es`, then to English, then to
the key itself. So a catalog can be partial, and a language can be added one
file at a time. Switching language re-renders every binding that called
`t()`, without a restart.

Everything in `design.md` about copy still applies. It applies in `en.json`
now, which has the side effect of putting every sentence the window says in
one file, where a note that restates its rows is a lot easier to spot.

`.claude/skills/omacontrol-testing/scripts/i18n-check.py` holds the two
sides to each other, and `/verify` and `/lint` both run it: a key used and
missing, a key kept and unused, a translation that lost a `%1`, a plural
entry read with `t()`, and — narrowly — a capitalised literal assigned
straight to a property a reader sees.

## What a key may not do

- **Never build a sentence out of pieces.** `"Showing the first " + n + " of
  " + total` cannot be translated: the order of the parts is the language's,
  not the code's. The sentence is one entry with holes —
  `"Showing the first %1 of %2."` — filled with `.arg()`. Spanish puts them
  where Spanish does.
- **Count with `tn()`, never with `n === 1 ?`.** A plural entry is an object
  of CLDR forms, `{"one": "%1 day", "other": "%1 days"}`, and `tn(key, n)`
  picks the form by the reader's language's rules — which are not English's
  in most of them. A form may leave its number out ("One application opens
  somewhere of its own."); then fill it with `.replace("%1", n)`, because
  `.arg()` on a string with no hole prints `QString::arg: Argument missing`
  to the journal.
- **One key per role, not per spelling.** "Mount" over the mount column and
  "Mount" on the button shared a key, and the column read *Montar* — the
  verb. If a word is a noun in one place and a verb in another, it is two
  keys.
- **The key is written out in full at the call.** `t(cond ? "a" : "b")` is a
  key nobody can grep for, and one the check cannot see; write
  `cond ? t("a") : t("b")`.
- **Dates take their pattern from the catalog.** `app.formatDate(date,
  pattern)` takes month and day names from the locale Omarchy's registry
  gives the language, and `common.longDate` says what order they go in:
  "November 5, 2026" is not "5 de noviembre de 2026" with the words swapped.

What is *not* a word stays where it is: units (`px`, `GHz`), product and
theme names, key caps (`Space`, `Esc` — the name printed on the key), and
the example values in placeholders that are syntax rather than prose. Those
read the same in every language, and a translator handed `"px"` can only
copy it.

## Words that come from lib/

A handful of things the reader sees are sentences `lib/` assembles — the
switch notes on Overview, the attention notices, the names of the Disk
slices, the message after adding a plugin. They come from the same catalog,
through `t key [args…]` in `core.sh`, which fills `%1`, `%2` the same way.

- **`i18n_load` before `par_run`.** `t` loads the catalog into an
  associative array once per call of the script, and only for a call that
  has something to say. A `$(t …)` runs in a subshell, so a reader that forks
  loads it first, in the parent — otherwise every child reads the catalog for
  itself. `state`, `state_slices` and `overview_state` already do.
- **The value travels as `--arg`.** A translated word reaches a jq program as
  a variable, never spliced into the filter. In a jq `sub()`, the
  replacement's `.` is the match, not the input: bind what you substitute
  first (`.model as $m | $ready | sub("%1"; $m)`).
- **A label that a page compares is not a label.** The Disk page asked
  `label === "Home"`, which stopped matching the moment the label was
  Spanish. Give the row an `id` and compare that.
- **`die` stays English.** Those are diagnostics, often wrapping a tool's own
  words, and the people who read them are filing an issue.

## The search index

`search_index` reads the section sources, which now hold keys. The awk keeps
a key marked with `\001` and the jq after it resolves the mark in the
catalog `i18n_catalog` merges — the same layering, from the same language
file, as the window's. That is the whole point: the index has to count
matches in the language the rows are drawn in, or a search counts eleven and
shows seven. The groups `state.sh` contributes (Output, Keybindings,
Applications…) take the keys of the headings they stand for, for the same
reason.

## Adding a language

Copy `i18n/en.json` to `i18n/<code>.json`, where the code is one from
Omarchy's registry (`/usr/share/omarchy/default/i18n/locales.json`) or its
base language (`es` serves every Spanish), and translate the values. Leave
out anything that reads the same; it falls back to English. Keep each `%1`,
give plural entries the forms the language needs, and run the check.

Before writing a word, look at what Omarchy calls the same thing in its own
catalogs under `default/i18n/`: Night light, Stay awake, workspace. A
desktop that names one thing two ways is worse than either name.
